CashOfferChat dynamic widget settings/domain sync fix

Apply this ZIP at the project root. Do not place it inside a nested folder.

This fix is for the issue where /client/settings saves, but the widget on sellmyhousetodayanywhere.com still shows old widget text such as "Seller Intake Assistant".

Files that must be updated:
1. src/app/api/widget/settings/route.ts
2. src/app/api/client/settings/route.ts
3. public/widget.js
4. src/app/sellmyhousetodayanywhere/page.tsx

Important confirmations before deploy:
- src/app/sellmyhousetodayanywhere/page.tsx should include data-site-id="smhta".
- public/widget.js should call /api/widget/settings with siteId, domain, url, and v query params.
- src/app/api/widget/settings/route.ts should include domain fallback and no-store cache headers.
- src/app/api/client/settings/route.ts should update all business_settings rows for the current business_id.

After deployment:
1. Log into the client portal.
2. Go to /client/settings.
3. Change Widget Title and save.
4. Open sellmyhousetodayanywhere.com in an incognito window.
5. Open the widget. The header should match the saved Widget Title.

Optional API test:
Open this in a browser after deployment:
https://www.cashofferchat.com/api/widget/settings?siteId=demo&domain=sellmyhousetodayanywhere.com

The JSON should show settings.widgetTitle equal to the value saved in /client/settings.
If the debug.resolvedSiteId is demo, that is fine as long as businessId and widgetTitle are correct.
If widgetTitle still says Seller Intake Assistant, then /client/settings is saving to a different business than the widget site is attached to.
